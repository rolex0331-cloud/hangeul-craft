# 한국어 프론트엔드 디자인

해외 기준으로 만든 UI는 한글이 들어가는 순간 어색해진다. 단어 중간에서 줄이 바뀌고, 영문 폰트 대체 글꼴로 한글이 뭉개지고, 번역체 문구가 들어간다. 이 스킬은 **한국 사용자가 봤을 때 "국내 서비스 같다"고 느끼는 화면**을 만드는 것이 목표다.

## 작업 순서

1. **맥락 파악**: 서비스 성격(소비자 앱 / 쇼핑몰 / B2B / 공공·기관 / 포트폴리오)과 톤(친근한 해요체 / 격식 있는 합니다체)을 정한다. 요청에 없으면 소비자 서비스는 해요체, 공공·B2B는 합니다체로 기본 설정한다.
2. **디자인 방향 선택**: 아래 "디자인 방향"에서 하나를 고르고 일관되게 밀고 간다. 흔한 AI 스타일(보라색 그라데이션, 무의미한 글래스모피즘, 이모지 남발)을 피한다.
3. **한글 기본기 적용**: 아래 "반드시 지킬 것"을 모두 적용한다. 예외 없음.
4. **국내 패턴 적용**: 화면 종류에 맞는 패턴을 `references/ui-patterns.md`에서 가져온다.
5. **연동이 필요하면**: 로그인·결제·지도·주소 검색은 `references/local-services.md`를 따른다.
6. **검사**: 결과 HTML/CSS/JSX에 대해 `scripts/check_korean.py`를 실행하고 나온 경고를 고친다.
   ```bash
   python scripts/check_korean.py <파일 또는 폴더>
   ```

## 반드시 지킬 것 (한글 기본기)

자세한 근거와 수치는 `references/typography.md`.

```css
html { -webkit-text-size-adjust: 100%; }
body {
  font-family: "Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont,
    system-ui, "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif;
  word-break: keep-all;        /* 한글 단어 중간 줄바꿈 방지 — 가장 중요 */
  overflow-wrap: break-word;   /* 긴 URL·영문이 넘치지 않게 */
  line-height: 1.6;            /* 본문. 한글은 영문보다 넉넉하게 */
  letter-spacing: -0.01em;
  -webkit-font-smoothing: antialiased;
}
h1, h2, h3 { line-height: 1.3; letter-spacing: -0.02em; text-wrap: balance; }
p { text-wrap: pretty; }
```

- `<html lang="ko">`를 반드시 넣는다. 스크린리더 발음과 브라우저 줄바꿈 규칙이 달라진다.
- 한글 폰트를 반드시 로드한다. 영문 전용 폰트(Inter, Poppins 등)만 지정하면 한글은 OS 기본 글꼴로 대체되어 화면마다 다르게 보인다. 영문 폰트를 쓰고 싶으면 앞에 두고 한글 폰트를 뒤에 반드시 이어 붙인다.
- 제목은 굵게(700~800) + 음수 자간. 한글 제목은 자간을 줄여야 단단해 보인다.
- 숫자가 정렬되어야 하는 곳(가격표, 표, 대시보드)은 `font-variant-numeric: tabular-nums;`.
- 버튼·태그처럼 짧은 텍스트는 `white-space: nowrap;`으로 두 줄 깨짐 방지.
- 최소 본문 크기 모바일 15~16px. 한국 사용자는 모바일 비중이 매우 높으므로 **모바일 우선**으로 설계한다.

## 한국어 UI 문구

- 번역체 금지: "~하는 것이 가능합니다" → "~할 수 있어요", "당신의" → 생략하거나 "내", "성공적으로 완료되었습니다" → "완료됐어요".
- 버튼은 동사로 짧게: "확인", "다음", "구매하기", "장바구니 담기", "무료로 시작하기". "제출" 대신 맥락에 맞는 말("신청하기", "문의 보내기").
- 한 화면 안에서 해요체·합니다체를 섞지 않는다.
- 더미 텍스트에 Lorem ipsum이나 영어를 쓰지 않는다. 실제 서비스처럼 자연스러운 한국어 예시 문구를 쓴다(예: "오늘 주문하면 내일 도착해요").
- 오류 메시지는 원인 + 해결 방법: "비밀번호가 틀렸어요. 다시 입력해 주세요."
- "~해주세요"보다 "~해 주세요"가 맞춤법상 바르다(보조용언 띄어쓰기). 둘 다 허용되나 한 서비스 안에서 통일한다.

## 국내 표기 형식

| 항목 | 표기 | 코드 |
|---|---|---|
| 가격 | 12,900원 (₩ 기호보다 "원" 접미가 일반적) | `n.toLocaleString('ko-KR') + '원'` |
| 큰 금액 | 1.2만 원, 3억 원 (대시보드 요약) | `Intl.NumberFormat('ko-KR', {notation:'compact'})` |
| 날짜 | 2026년 10월 18일 / 2026.10.18 | `toLocaleDateString('ko-KR')` → "2026. 10. 18." |
| 요일 | 10월 18일 (일) | `{weekday:'short'}` → "일" |
| 시간 | 오후 3:30 / 15:30 | `{hour:'numeric', minute:'2-digit'}` |
| 전화번호 | 010-1234-5678 | 입력 시 자동 하이픈 |
| 할인 | **20%** 12,900원 ~~16,000원~~ (할인율을 빨강으로 앞에) | |
| 주소 | 도로명 주소 + 상세 주소 (우편번호 검색 버튼) | 다음 우편번호 서비스 |

이름 입력란은 하나("이름")로 둔다. 성/이름 분리(First/Last name)는 해외 패턴이다.

## 디자인 방향 (하나만 골라 일관되게)

- **핀테크 미니멀 (토스 계열)**: 흰 배경, 큰 굵은 제목, 한 화면 한 가지 질문, 하단 고정 큰 CTA, 파랑 포인트 1색, 넉넉한 여백, 둥근 모서리 12~16px.
- **커머스 (쿠팡·무신사·컬리 계열)**: 정보 밀도 높음, 상품 그리드 2열(모바일), 할인율·배지·별점·리뷰 수 강조, 상단 검색바, 하단 탭바.
- **로컬·커뮤니티 (당근 계열)**: 따뜻한 오렌지 계열, 리스트형 카드, 친근한 해요체, 동네·거리 정보.
- **공공·기관**: KRDS(대한민국 정부 디자인 시스템) 스타일. 높은 대비, 명확한 위계, 합니다체, 접근성 최우선, 화려한 효과 금지.
- **에디토리얼·브랜드**: 명조 계열(Noto Serif KR, 마루부리) 제목 + 고딕 본문, 큰 타이포, 비대칭 레이아웃.

어떤 방향이든 색은 포인트 1~2색 + 회색 계조로 제한하고, 장식보다 위계(크기·굵기·여백)로 정보를 구분한다.

## 화면 유형별 빠른 체크

- **회원가입**: 약관 "전체 동의" + 개별 항목에 [필수]/[선택] 표시, 마케팅 수신 동의는 선택으로 분리. 소셜 로그인은 카카오 → 네이버 → 애플/구글 순이 일반적. → `references/ui-patterns.md`
- **쇼핑몰·결제**: 사업자 정보 푸터 필수(전자상거래법). 결제수단에 카드·간편결제(토스페이·카카오페이·네이버페이)·계좌이체.
- **랜딩 페이지**: 첫 화면에 핵심 가치 한 문장 + CTA. 신뢰 요소(누적 사용자 수, 언론 보도, 투자사 로고)는 국내에서 특히 효과적.
- **모바일**: 하단 고정 CTA는 `padding-bottom: env(safe-area-inset-bottom)` 포함.

## 하지 말 것

- 영문 폰트만 지정하고 한글 폰트 생략
- `word-break: keep-all` 누락 (가장 흔한 실수)
- `word-break: break-all` 사용 (한글을 글자 단위로 쪼갬)
- 대문자 변환(`text-transform: uppercase`)에 의존한 디자인 — 한글엔 효과 없음
- 영문 기준 좁은 행간(1.2~1.4)을 본문에 그대로 사용
- 번역체 문구, 영어 더미 텍스트, 해외식 날짜(10/18/2026)·이름 입력(First/Last)
